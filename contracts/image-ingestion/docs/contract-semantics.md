# Normative contract semantics

New IDs are lowercase UUID v4 strings; generate them before side effects and keep them stable across retries. Dates are RFC 3339 UTC with `Z`; schemas permit date-time shape but runtime must enforce UTC. SHA-256 is lowercase hex. Versions are monotonically increasing positive integers per asset; `schema_version` is the semantic contract release. New breaking fields/semantics require a new major version, migration plan and ChatGPT review. Readers reject unknown major versions. Producer/consumer updates and canonical promotion must be coordinated; do not silently add top-level fields.

## Normalized media and metadata

Original bytes are immutable and hashed before decoding. Detect using signatures; filename/declared MIME are hints. A mismatch is recorded in extractor extensions and routed by verified signature. Decode limits apply before allocating oversized rasters and across all pages. Decoder registry selection is deterministic by supported signature then configured priority; ambiguous ties are CONTRACT_MISMATCH.

`png-rgb-white-v1`: apply EXIF orientation once, convert to sRGB RGB 8-bit PNG, composite alpha on white, preserve original bytes/metadata separately. PDF renders at configured DPI (default 300), TIFF pages in source order; static image has page_number 1. No silent truncation, resizing or dropping pages to fit limits. Each page has positive dimensions and contiguous unique page numbers 1..N. Geometry in OCR blocks uses normalized coordinates [0,1], origin top-left, after rotation; polygons are four clockwise vertices, with no self-intersection. Preserve reading order in the blocks array. Unknown confidence is null, never fabricated zero. Provider-specific confidence must be documented and mapped to [0,1].

Decoder interfaces use temporary local pages; the orchestrator persists those pages and constructs `NormalizedMedia` with verified OneDrive references before commit. `original_sha256` hashes original bytes; per-page SHA hashes encoded normalized PNG bytes. Metadata is extracted from originals, not guessed from rendered pages. Missing values are null; raw EXIF maps are data only. Ambiguous capture timezone leaves captured_at null with capture_time_raw retained; do not invent UTC. Strip unapproved GPS and secrets before canonical persistence. All versions/options necessary to reproduce normalization and OCR must be recorded.

## OCR

Completed OCR: every normalized page has exactly one successful OCRPage, error null, full_text equals page texts joined by `\f` in page order. A page with no text is a successful empty string. Partial: at least one successful and one failed page, failed page text null/blocks empty/error non-null; full_text joins successful texts only, so consumers must use pages for source mapping. Failed: no successful pages, full_text null, result-level error non-null. If a provider fails globally, pages may be empty; otherwise failed-page entries identify affected pages. Skipped: pages empty, full_text null, error null. Reused: pages empty, full_text null, reused_from_result_id non-null; resolve original within the authorized scope and copy its approved search text/index metadata. Other statuses require reused_from_result_id null. Reuse targets must be successful results with matching processing fingerprint; reuse chains must be flattened to an original completed result.

OCR result asset/scope must match Registry; page numbers must match normalized pages. Disabling OCR still produces a completed ingestion with ocr.status skipped. Partial OCR makes ingestion partial. Fatal pre-OCR failure makes ingestion failed and permits normalized/ocr null; mandatory Registry/Audit/Index still exist. Errors do not invent successful output. Retrying a terminal OCR failure requires a new ingestion request/key.

## Registry, Audit and Index

Registry is the latest canonical snapshot. An accepted record can have null identity/storage/media; a completed nonduplicate record must have original, SHA and normalized media. Completed OCR must be completed/skipped/reused; partial requires partial OCR; failed requires a Registry error. Every copied object retains source version and provenance. Duplicate occurrence has `exact_duplicate_of`; original content may share a OneDrive blob, but never access grants. Perceptual hash algorithm and version travel with its value. Relationships resolve only within the same authorized scope.

Index metadata is byte-equivalent as a JSON value in all three records. `page_count` equals normalized page count once known. `ocr_status` is pending until a result exists, then matches that result. `media_type` is verified MIME once known. `text_sha256` hashes UTF-8 search_text if completed/partial/reused OCR text is available, including SHA of empty text; otherwise null. Failed, accepted, processing and skipped OCR rows have empty search_text. Index text must never contain OCR from a previous unrelated request. Tags are unique normalized application labels; languages use provider-supported BCP-47 tags. Index does not independently edit Registry metadata.

Audit `outcome` equals Registry status; its previous version is N−1. `source` equals Registry source; `registry_sha256` and `index_sha256` bind immutable files. Initial event uses asset_accepted; processing event processing_started; terminal event matches outcome or duplicate_reused. An Audit failure is a commit failure, not a best-effort logging warning. Provider attempts and operational logs may be separate telemetry, but cannot replace these canonical asset events.

JSON Schema validates shape; referential equality, sequential pages, status rules, hashes, scope authorization, duplicate fingerprints, predecessor links and time ordering must be enforced by application/repository validation and fault-injection tests. `extensions` accepts namespaced vendor data only, never authority-changing fields. Float NaN/Infinity are forbidden everywhere.

Perceptual hashing and routing use the exact issued rules in handoff/PACKET-1-ISSUED-CONTRACT.md. Resource limits are decode limits, not a rescaling target. The first normalized page supplies the advisory asset-level perceptual hash.

## Duplicate processing fingerprint

Compute SHA-256 of sorted compact UTF-8 JSON (no NaN) containing `original_sha256`, `normalization_profile`, `decoder_id`, `decoder_version`, `pdf_dpi`, `ocr_enabled`, `provider_id`, `provider_version`, `model`, sorted unique `languages`, `provider_profile_version`, `context_release_id` and `metadata_policy_version`. Retain explicit nulls. OCR `options_sha256` hashes the same OCR-only options subset: enabled, provider ID/version, model, languages and provider profile version, using these exact field names. Only completed OCR candidates are reused; disabled OCR may skip recognition but is not an OCR reuse candidate. Changed policy/profile requires a new fingerprint. Tenant/workspace authorization is checked separately and is never bypassed by a hash match.

Provider profiles are server-controlled versioned configuration. Request languages must be validated, unique and supported; order is normalized before computing request/options digests. Reserve using the normalized request so language order alone does not change request identity. Resolve profile versions/context once at admission and persist them with durable reservation metadata; an idempotent retry uses those pinned values even if the deployment defaults have changed. Decoder selection/configuration is pinned before reuse lookup; source signature inspection may precede that lookup without decoding.
